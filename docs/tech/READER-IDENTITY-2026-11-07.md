## Ownership boundary

[ADR 0005](../adr/0005-stable-reader-ownership.md) retains existing data owner keys. A provider identity is its exact verified issuer plus subject. An alias binds that pair to one stable reader owner; the same subject from a different issuer is a different identity. Historical administrator actor IDs remain provider actor references rather than reader accounts. No historical key, job token, reservation, audit entry or application row is rekeyed. Technical identity terms do not require a glossary change.

The parent supplied the narrow read-only preflight: the configured Clerk development instance is valid with three users, and Supabase has one matching development integration. That key does not establish production-instance absence or management authority. This task did not rediscover credentials or request owner setup. The supplied data inventory has three workspaces, 574 archive rows, seven daily snapshots and three reminder preferences; those are parent preflight facts, not a fresh production query from this checkout.

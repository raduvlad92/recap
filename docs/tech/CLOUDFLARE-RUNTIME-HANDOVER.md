# Cloudflare ownership and source runtime operations

Current checkpoint: 4 November 2026. PR #4 is merged as `194c9cf`, with checked-main shadow deployment and independent hosted preservation/off-state proof. Runtime operations below are implemented and locally tested. Live validation is metadata-only: no ownership transfer, source activation or apply workflow has run.

`scripts/cloudflare-handover-runtime.mjs` validates a ready plan and rehashes the original checked artifact before actions. Staging uploads exact jobs/web versions without serving them. Ownership transfer requires both exact staged active versions, the unchanged paused Netlify revision, empty hosting work, fresh external authorization/fence checks and acknowledged durable intent. It calls the already installed service-only `commit_hosting_handover_checked` function, which changes ownership to Cloudflare paused. No new database migration is introduced here.

Promotion keeps ownership paused, enables only the existing verified source version, then promotes jobs before web. It accepts only the prior inert or saved staged versions, exact flags/bindings and the known source image. Source enable/disable uses version deployment metadata; it never invokes the downloader or rebuilds the container. Resume requires the explicit resume policy, paused target revision, exact active Workers, verified enabled source and fresh external delivery/evidence/fence authorization. The executor must implement those checks and persist sub-operation intents before these primitives can be used live.

Transfer/resume/pause/restore use saved operation UUIDs. A lost successful reply reconciles only its own applied revision; an intervening operator revision stops progression. Resumed reconciliation permits legitimate new work without repeating resume or requiring frozen pre-switch domain rows. Recovery pause/restore metadata retains Cloudflare ownership and the old-host fence, advances the epoch when restoring another release and stays paused. These primitives do **not** establish a usable recovery artifact or restore its web/jobs/assets: that complete executor/readback remains unfinished. No lease, uncertain record or financial hold is cleared.

`cloudflare/verified-source-runtime.json` pins both known source versions, their matching provider script etag, runtime/binding hashes and the current container configuration hash/one-instance bound. The existing hosted-tested image and code hashes remain unchanged. `readSourceRuntime` independently verifies both immutable version settings, current serving bindings, private source identity and container configuration. Binding verification preserves the existing Durable Object namespace/daily counter. The pin is included in new artifact configuration hashes and mandatory for every executable active artifact; changing it invalidates saved artifact identity. Historical shadow artifacts remain inspectable and cannot satisfy active handover readiness.

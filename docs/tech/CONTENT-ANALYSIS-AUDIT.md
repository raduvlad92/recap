# Latest content: recap, keywords and Shorts audit

Reviewed **24 October 2026, Europe/Berlin**, using actual archive readback at **23 October, 22:01 UTC**, collection logs at **22:02 UTC**, the signed-in hosted page and current code. This is an investigation, not an implemented correction. [Sanitized evidence](evidence/content-analysis-audit.json).

## Findings

The archive contains 485 records, including 391 videos. The hourly collector added 207 videos: **92 with transcripts and 115 metadata-only**. All 207 lack `videoSummary`, stored `videoHighlights`, `videoKeywords` and `isShort`. All 21 followed YouTube sources have a saved `showShorts:false` preference.

1. **Missing recaps:** hourly collection retrieves metadata/captions but never invokes synthesized video analysis. Of the new arrivals, 115 lack the underlying transcript too. The signed-in Today view groups existing source descriptions under “Other updates”; it visibly includes sponsor/merchandise copy. Its rendering selects existing insights or `summary` strings, rather than generating a daily cross-source briefing. Daily generation remains unfinished.
2. **Missing keywords:** the new-content pipeline never generates `videoKeywords`. Keywords on 132 older videos came from the one-off D25 LMG analysis batch, with the D28 reference correction. The current missing rows have no keywords to display; no evidence attributes this to the scrolling footer or pending admin review.
3. **Shorts despite the preference:** the preference is saved correctly. Hourly RSS normalization constructs `/watch?v=…` URLs and omits Shorts classification. The reader hides an item only when `isShort:true` or a canonical `/shorts/…` URL identifies it. Unknown items therefore pass the filter. All 207 newly imported videos have that unknown classification. The live Today view even includes a source description containing `#shorts`. Duration alone does not establish a YouTube Short.
4. **Bullets without keywords:** `getVideoHighlights()` independently falls back to selected transcript sentences, while `getVideoKeywords()` only reads saved keywords. Replaying the actual renderer helpers produces bullets on all 92 new captioned videos and keywords on none. The live “Nintendo might be cooked too” card has six such excerpts, no stored analysis and no keywords. These are not the concise synthesized findings requested in D25.

## Recommended repair order

1. Repair classification consistently in all collection paths and guarded archive enrichment; preserve preferences and existing positive evidence. Reuse existing stored supplier evidence where available. Give unknown classification an explicit state rather than silently promising that “No Shorts” is enforced.
2. Add a bounded, retryable analysis stage after usable content arrives, keyed by content hash/rule version. Generate concise takeaways and independently reviewed full-content keywords; retain admin decisions. Backfill the already-collected captions without recollecting them.
3. Distinguish captions pending/unavailable, analysis pending/failed, reviewed summaries and source excerpts. Reconcile unresolved caption jobs and the 115-item backlog within the existing caps.
4. Implement actual cited cross-source daily briefing assembly separately from video-card analysis.

These are recommendations, not a new provider/model/budget authorization. No app, schema, archive, settings, supplier runtime or spending limits were changed. No supplier/model job was started by the review; existing hourly automation continues independently. The browser was returned to its original search/view. Raw archive, private identities, follows and credentials are excluded from the saved evidence. Supabase connector accounts did not expose this project; readback used existing local server credentials after verifying the exact project and verified owner. No new authentication was requested.

## Proposed repair scope — founder requested suggestions, 24 October

Recommend completing the automatic processing flow before further card styling or another isolated annotation batch. The founder has requested recommendations here, not authorized this proposal's implementation or new paid AI execution.

1. **Dependable Shorts exclusion and truthful processing states.** Store short/regular/unknown classification with its evidence across every importer and archive update. Respect existing preferences when a channel is added again. With No Shorts selected, retain unknown-format videos in an inspectable “format being checked” section outside the main feed/briefing until classification completes. This can delay regular videos; do not silently hide the delay or infer format solely from duration. Preserve all archive items and original links. Expose distinct content, recap and keyword states, including temporary failure and budget pause. Existing source excerpts remain explicitly inspectable as source material.
2. **Automatic analysis whenever usable content arrives.** Run full-content concise takeaway generation and full-content keyword extraction as separate tasks, with the independent blind keyword inventory and existing private uncertainty review. Real caption/chapter links support takeaways. A pending keyword review must not block an otherwise valid summary; show each task's actual state. Key work to the source identity, content hash and rule version; prevent duplicate charges, retry bounded failures, invalidate stale unavailable/ready annotations when content changes, and keep prior admin decisions for the matching source revision. Never create full-content claims from descriptions alone.
3. **Repair existing coverage without recollecting available captions.** Queue the 92 newly captioned videos plus other eligible missing/stale analyses. Preserve valid existing summaries and original captions. Bring legacy keyword inventories onto the current entities-v2 rule through reviewed reprocessing while preserving admin corrections. Recover the 115 pending transcripts separately: reconcile the four unresolved supplier jobs before retrying, retain unknown-charge holds, handle oversized transport responses safely, and distinguish temporary retrieval failure from confirmed unavailable captions. Prioritize current eligible arrivals so backfill cannot consume their entire operating allowance. Do not analyze excluded Shorts merely to clear a queue count.
4. **Genuine daily briefing after per-item analysis works.** At the reader's chosen local cutoff, assemble up to five useful topics from supported analyzed content, prioritized by explicit interests. Use original-update citations and underlying caption/text evidence; combining generated summaries cannot establish independent corroboration. Keep dated history, explain late arrivals and incomplete coverage, and leave all eligible updates reachable. Disclosed sponsors stay distinct from ordinary brand mentions; sponsorship copy is excluded from editorial takeaways but explicit sponsor/name mentions remain eligible keywords. The daily briefing and optional email delivery have separate completion evidence.
5. **Prove operation and cost.** Run a bounded quality/cost evaluation before ongoing paid model execution. Collection and AI need separate visible caps and reconciliation inside any expressly approved overall budget; the existing supplier ceiling does not itself authorize model spending. Measure cost per usable analyzed item and per briefing before suggesting a steady-state budget. Acceptance covers a real new regular video through discovery → content → recap/keywords → briefing, a Short and an unknown-format item under exclusion, caption failure/recovery, content revision, admin decision preservation, duplicate delivery, budget pause, reload and account isolation. Then observe at least 48 hours of hosted operation rather than treating fixtures or a manual batch as automatic-flow proof.

Suggested delivery: first ship classification, status and repeatable per-item processing/backfill; then daily briefing assembly once that input is dependable. No provider switch, new subscription or cost increase is a prerequisite to the code/persistence corrections. Remaining access or paid-model setup requirements should be determined from existing authorized resources, not sent to the founder as routine engineering tasks.

Independent read-only proposal review confirmed this sequence and added two acceptance cautions: verify caption completeness before treating any of the 92 transcript-bearing records as full-video coverage; processing all saved characters does not prove the supplier retrieved the entire original. Clearly label partial/unverified inputs. Also, strict unknown-format exclusion can temporarily withhold all 207 audited arrivals, so the pending count and inspection control are necessary. Genuine promotional-only/no-finding content may correctly have no takeaways. Annotation repairs must tolerate concurrent hourly imports and must not recreate deleted records or overwrite original media, workspace changes or admin decisions.

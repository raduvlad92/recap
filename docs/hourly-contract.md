# Hourly collection integration contract — 23 October 2026

Backend worker owns the new hourly module, scheduled dispatcher/background function, migrations and backend tests. This document describes the pending local migration; no production activation or supplier execution is implied.

## Policy and reporting tables

- `reader_collection_policies`: `user_id text` PK, `enabled boolean default false`, `provider_enabled boolean default false`, `daily_limit_usd numeric default 0.10` (database maximum 0.10), `lifetime_limit_usd numeric default 1.00` (database maximum 45), `created_at`, `updated_at`. Server-only writes; authenticated own-row SELECT. Daily accounting uses UTC days; unknown launched charges retain their full maximum in daily and lifetime commitment. Policies are explicitly inserted by the parent for the verified owner; no first-user or catalogue auto-enablement.
- `reader_collection_checks`: `id uuid` PK, `user_id`, `source_id`, `source_name`, `source_url`, `platform`, `status` (`running`, `unchanged`, `collected`, `partial`, `unsupported`, `blocked`, `failed`, `abandoned`), `started_at`, `finished_at`, `duration_ms`, `new_count`, `retrieved_count`, `http_status`, `error_code`, `provider` (`native`, `apify`, `none`), `job_id uuid nullable` -> `collection_jobs`, `provider_run_id text nullable`, `observed_cost_usd numeric nullable`, `cost_status` (`no_provider_charge`, `provider_reported`, `unknown`), `details jsonb`. Source names/URLs are public-source metadata; user IDs remain private. Own-row SELECT, server-only writes.
- `reader_collection_provider_jobs`: private server-only signed poll tokens and global-budget reservation references. Reporting must not expose this table/token. Public-safe reporting lives in checks + existing collection_jobs.
- `reader_collection_source_state`: private server-only per-user/source lease, feed validators, channel ID, identity fingerprint and cursor. `reader_collection_seen_items` stores per-user/source canonical item keys and archive IDs to deduplicate baseline/live results.

`new_count` counts previously unseen original item identities discovered during that check; `retrieved_count` counts real archive inserts or real transcript enrichments, not metadata claims or invented summaries. Native-only checks explicitly record supplier cost zero; hosting/database totals stay unmeasured. Unsupported X/Instagram checks record `unsupported`/`freshness_check_unavailable`, not `unchanged`.

## Cost attribution and aggregation

A native check has no `collection_jobs` row. Provider submission creates exactly one collection_jobs child per previously unseen YouTube video. Its check links `job_id`/`provider_run_id` when there is exactly one; multiple children appear as sanitized `details.providerJobs` references. The provider child has the authoritative supplier charge in `collection_jobs`; check cost is a display mirror and MUST NOT be added again to job totals. For check-only reports, aggregate check mirrors once per check; unknown costs remain null with an explicit unknown count and held maximum. Reserved amounts are commitments, never incurred charges. Global source-proof $45 ledger is unchanged and enforced in addition to policy limits.

## Activation / dispatch

`HOURLY_COLLECTION_ENABLED=true` gates all scheduled work. Hourly dispatcher at minute 0 UTC calls an authenticated background worker using `HOURLY_COLLECTION_WORKER_SECRET` (minimum 32 chars); background worker verifies the header and ignores request-supplied identities/source URLs. Worker reads enabled policies and authoritative reader_workspaces customSources intersected with followedSourceIds anew on each run. No catalogue sweep and no static source list. Parent owns enabling verified owner policy, production migration/configuration and approved provider configuration. Provider remains OFF unless both policy.provider_enabled and `HOURLY_COLLECTION_PROVIDER_VERIFIED=true`, plus existing Apify configuration gates, are valid.

The backend will use existing startApify/pollApify for bounded single-video jobs only, with maxItems=1 enforced by the hourly caller/config gate. Feed/YouTube freshness checks precede provider calls; unchanged responses never launch providers. The parent can update feed.ts/apify.ts; no new provider is assumed or activated by this module.

## Safe check details (final reporting shape)

`details.providerJobs` is an array of `{ jobId: string, providerRunId: string|null, actorId: string, itemKey: string, reservedUsd: number, observedCostUsd: number|null, costStatus: 'unknown'|'provider_reported' }`. All children are existing `collection_jobs` rows; don't add these cost mirrors to job totals. `details.reservedUsd` is the sum of maximum holds for those children, not spending. `details` may additionally contain `mode: 'native_feed'|'youtube_rss'|'unsupported'`, `captionStatus: string`, `gapPossible: boolean`, `deferredCount: number`, `invalidCount: number`, `coverage: string`, `httpNotModified: boolean`. Serialize those fields explicitly, never arbitrary JSON or private provider tokens. No reader private IDs other than the row's owned user_id are stored in details.

The native transcript hook and bounded provider adapter operate only on previously unseen canonical video IDs. Default fallback uses one exact video per run rather than a channel sweep; the parent may substitute a reviewed bounded batch adapter if it preserves per-item dedup, durable pre-POST budget reservation and authoritative job attribution.

## Final integration corrections

`reader_collection_source_state.pending_captions` is a private JSON array of `{ record: SourceUpdate, attempts: number, nextAttemptAt: string }`. Discovery archives honest metadata, while unfinished caption retrieval remains independently retryable before HTTP 304/body-hash exits. Failed native retrieval, provider review and reader/global budget stops retain the task; free native attempts back off from one hour to at most 24 hours. A source's existing paid item claim prevents every repeat POST, including ambiguous starts. Successful caption archive commit removes the queue task. Source-identity changes, archive deletion, workspace deletion and unfollow clear queues/fence pending content.

`reader_collection_provider_jobs.observed_cost_usd` retains the observed high-water separately from nullable terminal `actual_cost_usd`. Before settlement the worker reads the owned authoritative collection_jobs fee and takes the greatest prior/current observation. A database trigger prevents private observed/final amounts decreasing. A terminal missing fee keeps final cost null and the worst-case hold. Reader commitments use greatest(maximum, observation) while final cost is unknown, and greatest(final, observation) when known. The workspace-delete trigger takes the policy lock before source-state locks, matching reservation order.

It never reads application database credentials. It skips on environments without local PostgreSQL 17 tools or where initdb cannot run as a non-root user.

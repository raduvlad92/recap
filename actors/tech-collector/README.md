# recap tech collector

Private Apify Actor for the explicitly authorized D22 public tech-source backfill. It orchestrates reviewed, pinned providers; it is not a general web crawler. Creating or building this project does not run collection. No schedule, subscription, AI call, generated transcript or Supabase credential is included.

## Operator handoff

Prepare a JSON inventory containing `sources: [{ id, name, url, platform, channelId?, aliases? }]`. Identity research supplies the exact channel URLs, optional directly observed YouTube channel IDs and official aliases. Studios and presenters are not inferred from post mentions. Only YouTube, X and Instagram are accepted. Keep the explicit inventory separate from a claim that every related account has been found.

`node scripts/tech-backfill-input.mjs --sources <inventory.json> --output <ignored-input.json>` prepares the last 30 UTC days offline. Execution defaults false. `--execute --reservation <opaque-reservation-id>` changes that input only; it does not launch a job. Reserve the whole envelope in the application budget ledger before an operator starts this private Actor. Never put a reader email, private account ID or token in the input.

The parent must be launched with API `memory=256`, `timeout=3600` and `maxTotalChargeUsd=2` (or a lower positive cap matching `parentMaxChargeUsd`). The combined input ceiling is at most $45; $2 is reserved for parent compute/storage and the rest is available for child reservations. The input ceiling does not raise account quotas or buy a plan. Stop and report partial coverage if account credit or any cap is exhausted.

The date operators overfetch the UTC boundary days; returned posts are independently filtered to the exact requested instants. These results establish adapter compatibility, not complete 30-day access for every account. The old `apidojo/twitter-scraper-lite` review remains available for historical runs and demo-only evidence; it is no longer the launch default. Xquik charges platform usage separately. No paid transcription, AI enrichment or media download option is enabled. Existing YouTube subtitles are requested inline; missing subtitles remain metadata-only. Instagram captions and X public post text are text coverage, not media transcripts or linked-article bodies.

## Spending, failures and resumption

`CHECKPOINT` in the parent run's default key-value store records an immutable input fingerprint, parent run ID and each worst-case child reservation **before** the non-idempotent launch request. Each child launch has its own API dollar cap and pinned build number. YouTube and Instagram use 1GB memory and a ten-minute timeout; Xquik requires exactly 256MB and uses a two-minute timeout. The parent cap covers its own platform charges; children are separately reserved inside the combined ceiling. The API documents `maxTotalChargeUsd` across pricing models. The application must still reserve against other concurrent/root runs; this Actor's KVS is not a cross-run transactional budget database.

Every submitted child keeps its **full API charge cap reserved for the entire parent run**, including successful children with a reported zero or a low charge. Authenticated `usageTotalUsd` and `costObservedAt` are separate observations, never permission to reuse spending capacity. Missing costs remain null. During the first D22 run a terminal YouTube fee observation rose from $0.163 to $0.1736 on a later read; terminal status does not establish final billing. The manifest marks observed fees as non-final. Refreshed operator reads can improve the report, but do not release reservations inside this Actor or establish an irrevocably settled invoice. This code applies to future builds; it does not change the earlier live image or its execution evidence.

Before any child request, the manifest/checkpoint records the planned full per-source cap total. With the current 39-source inventory, 300 items per source, the Xquik default and a $0.40 parent cap, that full plan is **$40.77**. The earlier all-legacy provider plan was $41.63 for 39 sources and $40.04 for the original 38-source input; those historical reservations are not repriced by changing the default. The planner always uses the explicitly supplied inventory. The global item limit can stop earlier. A smaller input such as $4.70 remains $4.70 and is labeled `partialBudgetRun`; unaffordable sources are explicitly skipped. The Actor never raises its input budget, purchases account credit, changes account quotas or launches another run to finish a partial backfill. `committedUsd` reports held caps, while `observedChildCostUsd` is an incomplete point-in-time subtotal. Build charges and other concurrent runs still belong in the application's global reservation.

A response-lost start keeps its reservation and is not retried; an operator must reconcile it. A resumed same-run checkpoint polls recorded child IDs and never starts an ambiguous submission again. A checkpoint whose held full caps already exceed its own declared ceiling is rejected before any additional provider request. Different input/run IDs cannot reuse this checkpoint. Provider build mismatches are aborted and never ingested.

`OUTPUT` is the authoritative `{manifest, coverage, updates}` JSON record. Every normalized update uses the app's `SourceUpdate` fields, real original link, source ID and explicit content level. It contains no AI-written topics, brands, sponsors or invented presenters. Coverage includes provider status, earliest observed date, cutoff evidence, rejected dates/identities, caps, content levels, actual run/build references and reported/unknown costs. **`complete` remains false**: neither success nor a short result set proves exhaustive public-platform history.

Supplier `{demo: true}` placeholders are rejected as `provider_demo_data`. A dataset containing only these placeholders has coverage `provider_demo_only`, zero accepted content and a failed reader source status, even if the supplier run succeeded. A mix of real and demo records retains real updates but exposes a partial failure. The reviewed YouTube diagnostics `CHANNEL_HAS_NO_SHORTS`, `CHANNEL_HAS_NO_LIVE_VIDEOS`, `CHANNEL_HAS_NO_VIDEOS` and `DATE_FILTER_TOO_STRICT` are recorded separately as empty-format/date reports. They produce `no_items_reported` when no real updates remain, do not consume the content allowance merely by being diagnostic rows, and keep the reader source pending. They establish neither exhaustive history nor a verified quiet month. Unknown errors and failed supplier runs remain failures.

The observed Instagram `error: "no_items"` response means **empty or private data**, which does not establish whether an account was quiet or inaccessible. Only this exact code with matching requested-profile URL anchors is classified as `no_items_reported`; a successful run without independent request errors remains pending with zero accepted content and `complete: false`. A nonempty `requestErrorMessages` array is retained as a controlled `provider_request_error` record count and keeps coverage `failed_or_partial`. The raw error text is not copied. Missing/mismatched profile anchors, other error codes and failed supplier runs remain failures. These diagnostic rows do not themselves trigger a content cap.

Previously fetched raw datasets can be classified again **offline** with the pure `sourceCoverage(source, recordedEntry, rawItems, validatedOriginalInput, datasetWasTruncated)` export. Use the original input and recorded run entry, preserve run/build IDs and charge observations, and write a new derived output under a different path. Replace only the affected coverage/normalized updates, recompute `manifest.updateCount`, and record the normalization version and the original output hash in the derived manifest. Do not overwrite the raw dataset or original OUTPUT, relaunch the supplier, fabricate a new cost observation time, or imply this classifier ran inside an older image. Apply the importer to the validated derived output only after comparing the affected counts and retained IDs.

Selected source text is capped at 200,000 characters. When this clips an existing transcript, post/caption or video description, the update's coverage text explicitly says the remaining text is not included; source coverage records `clippedItems` and a matching notice. A transcript label describes the material's type, not a claim that the entire transcript was retained. The private archive provisioner separately rejects records larger than 1,000,000 JSON bytes without truncating them; the matching database limit must be applied before import.

The default dataset contains `recordType: source-update`, `coverage` and `manifest` records. Final publication is checkpointed. If dataset publication is interrupted, it is not blindly replayed; use canonical KVS OUTPUT and its publication warning. Upstream provider datasets can contain additional raw fields; they are not copied into our normalized dataset. Raw-input retention and upstream deletion remain application/operator responsibilities.
